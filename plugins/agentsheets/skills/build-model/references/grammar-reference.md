# Readable formula reference

The inventory of spellings the parser accepts; normative for syntax. Meaning
and choice live in `formula-grammar.md` beside it.

## Formula shapes

Every authored string parses at one of these entry points. Match the shape to the
field you are filling.

| Shape | Authored in | Example |
| --- | --- | --- |
| Expression | formula bodies: variable formulas, defaults, rollups | `Revenue - COGS` |
| Condition | the condition half of a formula write | `[]` |
| Dimension predicate | one predicate in a predicate editor | `Region = "West"` |
| Predicate value | the operator and right side beside an already-chosen dimension | `in {"East", "West"}` |
| Reference | a single variable or dimension reference with no surrounding arithmetic | `Revenue$[Region = "West"]` |
| Cell address | reading and matching one variable's rules; set_values builds this shape for you from variable, grain, period and segments | `Revenue[]` |
| Breakdown | the breakdown field of a view: how a table splits what it measures | `[Department, {Level[Department = "Engineering"], Owner}]` |
| Predicate list | a field that holds several predicates at once, with no brackets around them | `Region = "West", Department = "Engineering"` |

## Reference forms

How a formula names a variable, a dimension, or an external column.

| Form | Meaning |
| --- | --- |
| `Revenue` | Current-segment value; shorthand for `this.Revenue` |
| `` `Net Revenue` `` | Backtick name, for spaces, punctuation, or a reserved word |
| `Revenue#a3f` | Hex disambiguator, when several properties share one name |
| `Revenue$` | Absolute reference; does not inherit the current segment |
| `this.Revenue` | Dot access: explicit current segment read, and the granularity suffix |
| `Date.Day … Date.Year` | Granularity pin: `.Day` `.Week` `.Month` `.Quarter` `.Half` `.Year`, exact case |
| `Revenue[Region = "West"]` | Bracket lookup: dimension predicates, or a date offset |
| `<runway:properties/UUID>` | Raw property URI. Storage form; read it, but author readable names |
| `<exttable:ID/column>` | Shorthand for an external column; lowers to the URI form. Only letters, digits, `_` and `-`, so names with spaces need the URI |
| `<runway:exttables/UUID/columns/Name/>` | External-table column. Plain reference only: no postfix `$`, `[…]`, or dot after the closing `>` |
| `// note` | Comments: `//` to end of line, `/* … */` across lines |

## Table views: breakdowns

A table is declared as a view: `variables`, the value axis, and `breakdown` strings — one per entry for its rows, one shared for the columns. Each `variables` entry carries exactly one of `variable`, a readable name spelled like any reference above, or `dimension`, which places a dimension on the value axis as a mapping: its cells show that dimension's item for the row and column rather than a measured value, and a mapping takes no breakdown of its own. A breakdown is bracketed and built from the forms below. A view says what the table computes and nothing else: window, comparison, and sort are typed fields on the table tools, never part of the breakdown.

| Form | Meaning |
| --- | --- |
| `[Department]` | Split by one dimension: one row per Department item |
| `` [`Spend Type`] `` | Backticks quote a name with spaces; written bare, the parse stops at the second word |
| `[Department, Level]` | A comma descends: Levels nest under each Department |
| `[Department, {Level, Owner}]` | Braces fork: Level and Owner sit side by side under each Department, and whatever follows the brace applies to every branch |
| `Level[Department = "Engineering"]` | A branch condition routes a term under ONE branch of a dimension above it — Engineering gets Levels while other branches do not |
| `Region in {East, West}` | An item filter keeps only the listed items of the term's own dimension |
| `[Date.Month]` | A grain buckets a date dimension; Day, Week, Month, Quarter, Half, or Year |
| `{Level, [Owner, Date.Month]}` | A branch that descends is bracketed: Owner splits by month while Level does not |

## Grammar

The productions the parser actually uses, renamed for reading. Terminals are shown as the text you write.

```ebnf
expression         = value
                   | "not" expression
                   | expression "and" expression
                   | expression "or" expression
value              = "(" expression ")"
                   | function "(" (expression ("," expression)*)? ")"
                   | "-" value
                   | value "^" value
                   | value "%"
                   | value ("%" | "*" | "/") value
                   | value ("+" | "-") value
                   | value ( "<" | "<=" | ">" | ">=" | "=" | "<>" ) value
                   | value "not"? "in" membership
                   | "this" "." name (dot-chain ("where" expression)?)?
                   | "$"? "[" predicate ("," predicate)* "]" dot-chain
                   | offset
                   | reference
                   | number
                   | "null"
                   | string
                   | set
reference          = name "$"? (dot-chain ("where" expression)?)?
                   | exttable-uri
                   | name "$"? lookup-suffix dot-chain? ( "where" expression )?
lookup-suffix      = "[" predicates? "]" (name? offset)?
                   | offset
condition          = "$"? "[" (predicate ("," predicate)*)? "]"
cell-address       = name condition
predicates         = predicate ("," predicate)*
predicate          = name dot-chain? predicate-value
predicate-value    = ( "=" | "<>" | "<" | "<=" | ">" | ">=" ) value
                   | "not"? "in" "any"
                   | "not"? "in" membership
                   | "where" expression
membership         = range
                   | set
range              = value ":" value
offset             = "[" expression "]"
dot-chain          = "." name ("." name)*
set                = "{" "}"
                   | "{" expression ("," expression)* "}"
name               = (identifier | backtick-name | granularity) "#hex"?
breakdown          = "[" breakdown-sequence "]"
breakdown-sequence = breakdown-node ("," breakdown-node)*
breakdown-node     = breakdown-term
                   | fork
fork               = "{" branch ("," branch)+ "}"
branch             = breakdown-term
                   | "[" breakdown-term ("," breakdown-node)* "]"
breakdown-term     = name dot-chain? branch-condition? item-filter?
branch-condition   = "[" predicate "]"
```

## Expression composition

The Grammar productions are the whole truth about nesting; these are the
consequences that are easy to read past.

- Function arguments are full expressions, so lookups, nested calls, and bare `and`/`or` are all legal inside `f( … )`.
- A condition is one bracketed group. `[]` is the whole-model default and matches every segmentation. `[Dim in any]` claims a shape: it matches any segmentation containing the named dimensions and survives added drill-ins. `$[...]` claims a place: it matches exactly the named set, so use it for cell pins and pasted-back read addresses that must stop applying when the grain changes. `$[]` matches only the empty segmentation. A condition never appears inside an expression.
- **Bracket fallthrough.** A bracket that matches no predicate shape still parses, as a date offset. `Revenue[Flag = (Active and Open)]` is a predicate lookup, while `Revenue[Flag = Active and Open]` parses as an offset expression instead. A clean parse is not proof the bracket means what you intended, so confirm against the dry run's canonical echo.
- A cell address is a variable followed by one condition, which is why a read echoes `Variable[condition] = expression` and why pasting that condition back into a write updates that rule rather than adding one. The condition carries its own brackets; a second bracket group is a parse error, not a second term group.
- **Dimension items.** `$[Location = "East Coast"].Location` is a dimension-item literal: it pins one dimension to a string and looks that dimension back up, evaluating to the pinned value. Prefer this notation over a bare string whenever it could be ambiguous whether a dimension item is intended (comparisons like `this.Location = …`, values fed to filters); a bare `"East Coast"` is just text, while the literal names its dimension. Always write the `$` form: it evaluates the pinned segment absolutely, while omitting the `$` composes the pin with the current segment, so the result can depend on where the formula runs. Looking up a different property (`$[Location = "East Coast"].Revenue`) evaluates as that property's lookup at the pinned segment, like `Revenue$[Location = "East Coast"]`.
- **Mapped dimensions read like values.** When a dimension's items come from a mapping (a lookup keyed by other dimensions), a lookup of it evaluates to its mapped item: `Bucket[Account = "5001"]` is that account's bucket. Dot access is the same read — `this.Bucket` is the current segment's mapped item when the segment carries the keys, and each dot hop desugars to a lookup keyed by the previous value, so `this.Account.Bucket` is `Bucket[Account = this.Account]`, and hops keep going where mappings chain. In a predicate the mapping runs the other way: `sum(Amount[Bucket = "COGS"])` gathers every source row whose account the mapping puts in COGS.

| Formula | Composes |
| --- | --- |
| `sum(Revenue[Department in any])` | lookup inside a call |
| `Revenue / sum(Revenue$[Region in any])` | share of total: absolute plus wildcard |
| `(Revenue - Revenue[-1]) / Revenue[-1]` | date offsets in arithmetic |
| `if(Tier in 1:3, 1, 0)` | range membership |
| `sum(Revenue[Date.Month where Date.Month <= this.Date.Month])` | where predicate with a current segment chain |
| `` if(this.Date.Month = date(2026, 1, 1), 250000 + `Net Cash Flow`, `Cash Balance`[-1] + `Net Cash Flow`) `` | recurrence: date-pin branch, offsets, backticks |

## Functions

Author the canonical name. Accepted names still parse in stored formulas.

### Aggregation

- `sum(value: number, value2...: number) -> number`: Returns the sum of one or more numeric expressions across the selected values.
- `product(value: number, value2...: number) -> number`: Returns the product of one or more numeric expressions across the selected values.
- `min(value: number, value2...: number) -> number | null`: Returns the smallest value across one or more numeric expressions, or null when no values exist.
- `max(value: number, value2...: number) -> number | null`: Returns the largest value across one or more numeric expressions, or null when no values exist.
- `average(value: number, value2...: number) -> number | null`: Returns the arithmetic mean of one or more numeric expressions across the selected values, or null when no values exist. *(accepted: `avg`)*
- `count(value: any, value2...: any) -> number`: Counts the non-empty values of one or more expressions, matching Excel COUNTA rather than Excel COUNT.
- `first(value: T) -> T | null`: Returns the first value in an expression's ordered series, or null when the series is empty.
- `last(value: T) -> T | null`: Returns the last value in an expression's ordered series, or null when the series is empty.
- `stdev(value: number, value2...: number) -> number | null`: Returns sample standard deviation (ddof=1) pooled across one or more numeric expressions, or null with fewer than two values. *(accepted: `stddev`)*
- `var(value: number, value2...: number) -> number | null`: Returns sample variance (ddof=1) pooled across one or more numeric expressions, or null with fewer than two values. *(accepted: `variance`)*
- `median(value: number) -> number | null`: Returns the median of a numeric expression, or null when no values exist.

### Math

- `abs(value: number) -> number`: Returns the absolute value of a numeric expression.
- `sqrt(value: number) -> number`: Returns the square root of a numeric expression.
- `ceiling(number: number, significance: number) -> number`: Rounds a number up to the nearest multiple of significance, matching Excel CEILING. `ceiling(UnitPrice, 0.05)`
- `floor(number: number, significance: number) -> number`: Rounds a number down to the nearest multiple of significance, matching Excel FLOOR. `floor(UnitPrice, 0.05)`
- `round(number: number, num_digits: number) -> number`: Rounds a number to a specified number of digits, matching Excel ROUND. `round(Forecast, 2)`

### Conditional

- `if(condition: any, whenTrue: T, whenFalse: U) -> T | U`: Returns one of two values depending on the condition's truthiness. `if(Revenue > 100, "high", "low")`
- `iferror(value: T, value_if_error: U) -> T | U`: Returns the value, or the fallback when evaluating the value produces an error. `iferror(datedif(StartDate, Date, "D"), 0)`

### Date parts

- `year(date: date) -> number`: Returns the year of a date as a number, matching Excel's YEAR.
- `month(date: date) -> number`: Returns the month of a date as a number from 1 to 12, matching Excel's MONTH.
- `day(date: date) -> number`: Returns the day of the month as a number from 1 to 31, matching Excel's DAY.
- `quarter(date: date) -> number`: Returns the calendar quarter of a date as a number from 1 to 4.
- `half(date: date) -> number`: Returns the calendar half-year of a date: 1 for January-June, 2 for July-December.
- `weekday(date: date, return_type?: number) -> number`: Returns the day of the week of a date as a number, matching Excel's WEEKDAY.
- `weeknum(date: date, return_type?: number) -> number`: Returns the week number of a date within its year, matching Excel's WEEKNUM.
- `isoweeknum(date: date) -> number`: Returns the ISO 8601 week number of a date, matching Excel's ISOWEEKNUM. Identical to WEEKNUM(date, 21).

### Date truncation

- `startofday(date: date) -> date`: Truncates a date to the start of its day.
- `startofweek(date: date) -> date`: Truncates a date to the start of its week.
- `startofmonth(date: date) -> date`: Truncates a date to the start of its month.
- `startofquarter(date: date) -> date`: Truncates a date to the start of its quarter.
- `startofhalf(date: date) -> date`: Truncates a date to the start of its half-year.
- `startofyear(date: date) -> date`: Truncates a date to the start of its year.

### Date arithmetic and construction

- `dateadd(date: date, amount: number, unit: string) -> date`: Shifts a date like Power BI's dateadd, with additional half-year support and quoted unit names. `dateadd(Date.Month, -1, "month")`
- `datedif(start_date: date, end_date: date, unit: string) -> number`: Returns the difference between two dates in the requested unit, matching Excel's DATEDIF. `datedif(StartDate, Date, "M")`
- `daysin(date: date, unit: string) -> number`: Returns the number of days in the unit-aligned period containing the date. `daysin(Date, "month")`
- `date(year: number, month: number, day: number) -> date`: Builds a date from year, month, and day numbers, matching Excel's DATE including month and day rollover. `date(2026, 1, 31)`
- `edate(date: date, months: number) -> date`: Shifts a date by whole months with the day clamped to the target month's length, matching Excel's EDATE. `edate(Date, -1)`
- `eomonth(date: date, months: number) -> date`: Returns the last day of the month a signed number of months from a date, matching Excel's EOMONTH. `eomonth(Date, 0)`
